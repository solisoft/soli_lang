# Builtins the runtime registers that one of the two hand-maintained lists does
# not know about yet. Read by `tests/builtin_registration_parity_test.rs`.
#
# This is a ratchet, in the same spirit as `scripts/unwrap_baseline.txt`: the
# test fails when a name appears that is not listed here, and it fails again
# when a name listed here has since been registered. So the file can only ever
# shrink, and a new builtin cannot be added without either registering it on
# both surfaces or saying here, in a commit, that it is deliberately absent.
#
# It is not a list of bugs. What is left in [type-checker] is the **test DSL**
# and nothing else — `describe`, `test`, `expect`, `assert_*`, the HTTP and
# browser helpers — and a test below holds it to exactly that. Those names
# exist only when the runtime is about to run tests (`register_builtins` takes
# the flag off when serving), so teaching them to every file would accept a
# spec-shaped call in a controller that cannot run it. `soli check` seeds them
# for a file `soli test` would run, and for no other.
#
# The rest of that section — 250 names, model and migration DSL, the
# `__`-prefixed internals, the whole ordinary surface — is gone because the
# checker no longer keeps a list at all: it derives the served namespace from
# `register_builtins` itself (see `src/types/runtime_globals.rs`). That is the
# class of bug this file was created to stop, after the ten `pdf_*` builtins
# and then `Image` / `File` / `Trusted` were each found by a user; on the
# type-checker side it can no longer happen.
#
# [linter] is still a hand-written list (`lint::rules::scope`), so that half of
# the ratchet is doing the job it was written for.
