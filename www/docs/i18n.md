# Internationalization

Translations with interpolation, CLDR pluralization, and locale-aware number,
currency and date formatting — built in, no package.

## Which locale a request runs in

A request begins with a locale already resolved for it, in this order:

1. a locale value in the **session** — the person picked it;
2. a locale **cookie**;
3. the best match for the **`Accept-Language`** header among the locales you
   ship. `fr-CA` is served by a `fr` you have, and a language you have no file
   for is skipped rather than negotiated to;
4. **`SOLI_DEFAULT_LOCALE`**, or `I18n.set_default_locale(...)`, defaulting to
   `en`.

The locale is restored when the request ends, so it never crosses from one
visitor to the next on the same worker. It used to: a controller that never
called `set_locale` rendered in whatever language the previous visitor had
asked for. Realtime frames — Live View and EUI — resolve it from the socket's
session the same way.

`I18n.set_locale` still overrides it for the rest of the request. **It is no
longer something you have to call** to avoid inheriting someone else's language.

```soli
I18n.locale()            # the locale resolved for this request
I18n.set_locale("fr")    # override it, for this request only
```

## Translating

`I18n.translate(key, locale?, translations?)` looks the key up, and falls back
to the key itself when there is no translation — so a missing string shows as
`nav.home` rather than as blank.

```soli
translations = {
  "en.greeting" => "Hello",
  "fr.greeting" => "Bonjour",
  "de.greeting" => "Hallo",
  "en.welcome"  => "Welcome to our app!",
  "fr.welcome"  => "Bienvenue dans notre application!"
}

I18n.set_locale("fr")
I18n.translate("greeting", null, translations)      # "Bonjour"
I18n.translate("greeting", "de", translations)      # "Hallo"
I18n.translate("unknown_key", null, translations)   # "unknown_key"
```

## Plurals follow CLDR

Which suffix a count selects depends on the **language**, not only on the
number. Soli uses the CLDR categories — `_zero`, `_one`, `_two`, `_few`,
`_many`, `_other` — and each language uses the ones it has:

- **French has no zero category**: 0 and 1 are both `_one`, so « 0 article » is
  singular.
- **English** has `_one` and `_other`; 0 takes `_other` — "0 items".
- **Russian and Polish** use `_few` and `_many`; **Arabic** uses all six;
  **Japanese and Chinese** use only `_other`.

Two conveniences on top. A `_zero` key is honoured for a count of 0 in *any*
language when you write one, because "No items" is often worth saying
differently. And a category your file does not declare falls back to `_other`
**in the same locale**, before any other language is consulted.

Before this, every language got English's zero/one/other: a French page with a
correct `fr.yml` asked for `items_zero`, did not find it, and rendered the
English string in its place.

```soli
translations = {
  "en.item_zero"  => "No items",
  "en.item_one"   => "1 item",
  "en.item_other" => "{count} items",
  "fr.item_one"   => "{count} article",
  "fr.item_other" => "{count} articles"
}

I18n.set_locale("en")
I18n.plural("item", 0, null, translations)   # "No items"
I18n.plural("item", 1, null, translations)   # "1 item"
I18n.plural("item", 5, null, translations)   # "{count} items"
I18n.plural("item", 3, "fr", translations)   # "{count} articles"
```

## Numbers, currency, dates

```soli
I18n.format_number(1234.56, "en")            # "1234.56"
I18n.format_number(1234.56, "fr")            # "1234,56"  (decimal separator only, no grouping)

I18n.format_currency(1999.99, "USD", "en")   # "$1,999.99"
I18n.format_currency(1999.99, "EUR", "fr")   # "1.999,99 €"  (plain space before €)
I18n.format_currency(2500, "JPY", "en")      # "¥2,500"

timestamp = 1768521600                       # 15 January 2026
I18n.format_date(timestamp, "en")            # "01/15/2026"
I18n.format_date(timestamp, "fr")            # "15/01/2026"
I18n.format_date(timestamp, "de")            # "15.01.2026"
I18n.format_date(timestamp, "ja")            # "2026-01-15"  (ISO default)
```

`DateTime.format` takes an optional locale too, when you want the pattern under
your own control and only the month and day names translated:

```soli
dt = DateTime.parse("2024-03-06T14:30:00Z")
dt.format("%A %d %B %Y")         # "Wednesday 06 March 2024"
dt.format("%A %d %B %Y", "fr")   # "mercredi 06 mars 2024"
dt.format("%A %d %B %Y", "es")   # "miércoles 06 marzo 2024"
```

Names are translated for `en`, `fr`, `es`, `de`, `it` and `pt`. Numeric
specifiers (`%Y`, `%m`, `%d`, `%H`, `%M`, `%S`) are unaffected by locale.

## Translation files

`config/locales/*.yml` files are loaded when the server starts, each keyed by
its locale, and `I18n.translate(key)` reads them when you pass no translations
hash:

```yaml
# config/locales/fr.yml
fr:
  nav:
    home: "Accueil"
```

```soli
I18n.translate("nav.home", "fr")   # "Accueil"
```

A file is read with `Yaml.parse` (see [Toml / Yaml](builtins.md#what-yamlparse-reads)),
which refuses anchors, aliases and `<<:` merge keys: a locale file that uses
them — or holds any other error — is skipped at boot with a warning naming the
file, line and column, and its keys are missing until it is fixed. Write the
shared keys out in each locale instead of aliasing them.

Under `soli serve --dev` an edit to one of these files — a new key, a new
locale file, even a `config/locales/` directory created after boot — is
picked up on save, with no restart: the workers reload the translations and
the browser reloads the page. In production they are read once, at boot.
`soli test` loads them too, so a spec sees the application's messages and
names.

A JSON file works too, loaded by hand and passed as the translations hash:

```json
{
  "en.app_name": "My Application",
  "en.nav.home": "Home",
  "en.messages.success": "Operation completed successfully!",
  "en.user.greeting": "Hello, {name}!",
  "en.items_one": "You have 1 item",
  "en.items_other": "You have {count} items"
}
```

```soli
en_translations  = json_decode(file_read("config/locales/en.json"))
fr_translations  = json_decode(file_read("config/locales/fr.json"))
all_translations = en_translations.merge(fr_translations)

I18n.translate("nav.home", "en", all_translations)   # "Home"
```

## Fallbacks between locales

A key missing in the request's locale is looked up along a chain: the locale,
the fallbacks you declare for it, its base language (`fr-CA` → `fr`), the
default locale, then English. `I18n.translate`, `I18n.plural`, the validation
messages and the model and attribute names all follow it.

```soli
I18n.set_fallbacks({"ca": ["es"], "pt-BR": "pt"})   # per application
I18n.locale_chain("ca")                             # ["ca", "es", "en"]
I18n.fallbacks()                                    # {ca => [es], pt-BR => [pt]}
```

Call `I18n.set_fallbacks` once, at boot (an initializer, or the top of
`config/routes.sl`). It replaces what was declared before.

## Validation messages

A model's validation errors read in the request's locale. Soli ships the
messages for `en`, `fr`, `de`, `es`, `it` and `pt`; an application with no
locale file gets them as they are:

```soli
I18n.set_locale("fr")
post = Post.new({"title": ""})
post.save
post._errors        # [{field => title, message => doit être rempli(e)}]
post.full_messages  # ["Title doit être rempli(e)"]
```

Each message has a code. Its sentence is looked up, in each locale of the
chain, under these keys — the first one found wins:

1. `models.<model>.errors.attributes.<field>.<code>` — one field of one model
2. `models.<model>.errors.<code>` — every field of one model
3. `errors.messages.<code>` — in your `config/locales/*.yml`
4. `errors.messages.<code>` — in the messages Soli ships

`<model>` is the class name in snake case (`BlogPost` → `blog_post`,
`Admin::User` → `admin/user`).

| Code | English | From |
|---|---|---|
| `blank` | can't be blank | `presence`, a NOT NULL column |
| `taken` | has already been taken | `uniqueness`, a unique index |
| `invalid` | is invalid | `format`, a custom validator returning `false` |
| `not_a_number` | is not a number | `numericality` |
| `too_short` | is too short (minimum is {count} characters) | `min_length` |
| `too_long` | is too long (maximum is {count} characters) | `max_length` |
| `greater_than_or_equal_to` | must be greater than or equal to {count} | `min` |
| `less_than_or_equal_to` | must be less than or equal to {count} | `max` |
| `inclusion` | is not included in the list | `inclusion` / `one_of` |
| `wrong_type` | must be {type} | `type:` — `{type}` reads `errors.types.<type>` ("an int", « entier ») |
| `value_object` / `value_object_list` | must be a {class} / must be a list of {class} | `value_field` |
| `foreign_key` | must reference an existing record | a foreign key |
| `still_referenced` | is still referenced by other records | a restricted delete |
| `stale` | is stale: the record was changed since it was read — reload it and try again | `optimistic_lock` |

`too_short` and `too_long` are plural keys (`too_short_one`,
`too_short_other`, …, chosen by the CLDR rules of the locale); a plain
`too_short` key is used for every count when you write one.

### Overriding a message, adding a language

Your locale files sit on top of the shipped messages, key by key. Write only
what you change:

```yaml
# config/locales/fr.yml
fr:
  errors:
    messages:
      blank: "est obligatoire"          # every model
  models:
    blog_post:
      errors:
        taken: "existe déjà"            # every field of BlogPost
        attributes:
          slug:
            taken: "est pris par un autre article"
```

A language Soli does not ship works as soon as a file declares it. A code the
file leaves out falls back along the chain, then to English, never to nothing:

```yaml
# config/locales/nl.yml
nl:
  errors:
    messages:
      blank: "moet opgegeven zijn"
      too_short_one: "is te kort (minimaal {count} teken)"
      too_short_other: "is te kort (minimaal {count} tekens)"
```

`soli i18n:export fr` writes the shipped French messages to
`config/locales/soli.fr.yml` as a starting point, and `soli i18n:missing nl`
lists the keys `nl` still lacks against your default locale (`--from en` to
choose), exiting 1 when something is missing:

```bash
soli i18n:export fr              # config/locales/soli.fr.yml (--force to overwrite)
soli i18n:missing nl             # nl: 3 of 25 keys of en missing …
soli i18n:missing de --from fr
```

### Your own messages

`message:` replaces what a rule says. A String is the sentence in every
locale; a Symbol is a key, looked up like a code:

```soli
class Post < Model
  validates("slug", {"format": "^[a-z-]+$", "message": :slug_format})
  validates("code", {"format": "^[A-Z]+$", "message": "must be upper case"})
end
```

```yaml
fr:
  errors:
    messages:
      slug_format: "ne doit contenir que des minuscules et des tirets"
```

A custom validator may return a Symbol too (`return :too_big if size > 10`),
or push `{"field": "size", "message": :too_big}` onto `@_errors`. A key nothing
translates shows as the key itself, so the gap is visible.

`I18n.translate("errors.messages.taken", "de")` reads the shipped messages as
well.

## Model and attribute names

```yaml
fr:
  models:
    blog_post:
      name_one: "Article"
      name_other: "Articles"
      attributes:
        title: "Titre"
```

```soli
BlogPost.human_name                   # "Article" ("Blog post" with no key)
BlogPost.human_name(3)                # "Articles"
BlogPost.human_attribute_name("title")   # "Titre" ("Title" with no key)
post.full_messages                    # ["Titre doit être rempli(e)", …]
```

`full_messages` joins the name and the message with `errors.format`
(`"{attribute} {message}"` in every shipped locale); an error on `_base` is
its message alone. The form builder uses both: `f.label("title")` reads the
translated name when the form's record is a model, and `f.error_summary()`
lists the full messages — "Title can't be blank" rather than "can't be blank".

## Translated model fields

A model field can hold one value per locale. Declare it in the class body
with `translate` (or `translates`, the Globalize/Mobility spelling), and the
field reads and writes in the request's locale:

```soli
class Article < Model
  translate "title", "body"
end

article = Article.create({"title": "Hello", "body": "Text"})

I18n.set_locale("fr")
article.title                 # "Hello" — no French yet, the column answers
article.title = "Bonjour"
article.title                 # "Bonjour" — read back before save
article.save

I18n.set_locale("de")
Article.find(article._key).title   # "Hello"
I18n.set_locale("fr")
Article.find(article._key).title   # "Bonjour"
```

`Article.translate("title", "body")` after the class does the same.

Where the values live:

- **The column** (`title`) holds the **default locale's** value
  (`SOLI_DEFAULT_LOCALE`, else `en`). It is also the fallback: a locale with no
  translation reads it. Because it stays current, `where({"title": …})`,
  `find_by`, a uniqueness rule or an index on `title` see what a default-locale
  reader sees.
- **`translated_fields`** holds the other locales, as
  `{"title": {"fr": "Bonjour", "es": "Hola"}}`, in the same document. A
  `create` can seed it directly:
  `Article.create({"title": "Hello", "translated_fields": {"title": {"fr": "Bonjour"}}})`.
- **A write** — `article.title = …`, `@title = …` in a method,
  `article.update({"title": …})`, `article.save({"title": …})`,
  `set_translation` — goes by the locale active **when you write**: in the
  default locale it writes the column; in another it is staged, and `save` /
  `update` merge it into `translated_fields`, keeping the locales already
  stored.
- **`create` / `new`** fill the column with what they are given. Run in
  another locale than the default, they store it as that locale's translation
  too: a record created in French stays French once someone writes its English
  title into the column.

A read looks along the locale's regional chain — the locale, its declared
fallbacks, its base language (`fr-CA` → `fr`) — for a staged value, then a
stored one, and then reads the column.

Records written before 2.43.2 may carry the default locale's value in
`translated_fields` (`{"title": {"en": …}}`), with a column frozen at what
`create` was given. A reader still sees the entry; the next default-locale write
moves it into the column. `Article.sync_translated_columns` moves them all in one
query per translated field, and returns how many records it rewrote (SoliDB):

```soli
Article.sync_translated_columns   # => 42 — run it once, from a migration or the console
```

### Reading and writing several locales

```soli
article.translation("title", "fr")         # "Bonjour" — that locale only, nil if none
article.translations("title")              # {en => Hello, fr => Bonjour, es => Hola} — en from the column
article.set_translation("title", "de", "Hallo")   # staged; save writes it
```

A form can edit several locales at once. `{"locale": "fr"}` on a field names
it `translated_fields[title][fr]` and fills it with that translation;
`update(params)` merges the hash it produces locale by locale:

```erb
<%- f.label("title", "Titre", {"locale": "fr"}) %>
<%- f.text_field("title", {"locale": "fr"}) %>
<%- f.text_field("title", {"locale": "es"}) %>
```

```soli
# PATCH /articles/:id
def update(req)
  @article = Article.find(params["id"])
  locales = {"fr": true, "es": true}   # permit names each locale it lets through
  @article.update(permit(params, {"translated_fields": {"title": locales}}))
end
```

### Querying translations

`where` compares the column. `where_translated` compares what a reader in the
current locale sees — the translation along the regional chain, else the
column — and `order_translated` sorts by it. Both chain like `where` and
`order`:

```soli
I18n.set_locale("fr")
Article.where_translated({"title": "Bonjour"}).all
Article.where({"published": true}).order_translated("title", "desc").limit(10).all
Article.missing_translations("es").all   # records lacking es for a translated field
```

Sorting a translated field compares what a reader expects, not raw code points:
case and accents are set aside, so `fr` gives Abricot, banane, Éclair, école,
Zèbre — where a plain comparison gives Abricot, Zèbre, banane, Éclair, école.
Values equal once folded are ordered as written. `order("title")` on a field the
model declares translated does the same, since the column is not what the page
shows. This is right for languages that file an accented letter with its base
letter (English, French, Spanish, Italian, Portuguese); Swedish `å ä ö` or
German `ß` are not placed by their alphabet. No index serves this sort: SoliDB
sorts the matching documents in memory, so filter and `limit` a large
collection.

These three are SoliDB-only: on the SQL adapters they are refused, as a raw
string `where` is (`order("title")` there sorts the column). A path in a string filter reaches one locale directly:
`Article.where("doc.translated_fields.title.fr == @t", {"t": "Bonjour"})`.

## Formats from your locale files

A locale file can set the number and date conventions of a language Soli
does not format, or change those of one it does. Only the locale's own file
(and its regional chain) is read — a format is never borrowed from the
default locale:

```yaml
nl:
  number:
    separator: ","          # decimal separator
    delimiter: "."          # thousands
    currency:
      format: "{unit} {amount}"
  date:
    format: "%d-%m-%Y"      # strftime
```

```soli
I18n.format_number(1234567.5, "nl")          # "1.234.567,5"
I18n.format_currency(1999.99, "EUR", "nl")   # "€ 1.999,99"
I18n.format_date(timestamp, "nl")            # "16-01-2026"
```

`number.currency.separator` / `.delimiter` override `number.*` for amounts.

## Method reference

| Call | Answers |
|---|---|
| `I18n.locale()` | the locale resolved for this request |
| `I18n.set_locale(code)` | overrides it for the rest of the request |
| `I18n.set_default_locale(code)` | the fallback when nothing else resolves |
| `I18n.set_fallbacks(hash)` / `I18n.fallbacks()` | the locales tried after each one |
| `I18n.locale_chain(code?)` | the locales a lookup tries, in order |
| `I18n.translate(key, locale?, translations?)` | the translation, or the key itself |
| `I18n.plural(key, n, locale?, translations?)` | the CLDR form for `n` in that language |
| `I18n.format_number(n, locale?)` | the locale's decimal separator — no thousands grouping (`1234567,891`) unless the locale file sets `number.delimiter` |
| `I18n.format_currency(amount, currency, locale?)` | `USD`, `EUR`, `GBP`, `JPY`, grouped (`$1,999.99`; `fr`/`de`: `1.999,99 €`) |
| `I18n.format_date(timestamp, locale?)` | a locale date string (`date.format` from the locale file when set) |
| `Model.human_name(count?)` / `Model.human_attribute_name(field)` | the model's / field's name in the current locale |
| `record.full_messages` | each error as a sentence naming its field |
| `record.translation(field, locale)` / `translations(field)` / `set_translation(field, locale, value)` | one locale / every locale / stage one |
| `Model.where_translated(hash)` / `order_translated(field, dir?)` / `missing_translations(locale)` | queries on translated fields (SoliDB) |
| `Model.sync_translated_columns` | move old default-locale entries of `translated_fields` into the column; returns the count (SoliDB) |
