# Internationalization

Translations with interpolation, CLDR pluralization, and locale-aware number,
currency and date formatting — built in, no package.

## Which locale a request runs in

A request begins with a locale already resolved for it, in this order:

1. a locale value in the **session** — the person picked it;
2. a locale **cookie**;
3. the best match for the **`Accept-Language`** header among the locales you
   ship. `fr-CA` is served by a `fr` you have, and a language you have no file
   for is skipped rather than negotiated to;
4. **`SOLI_DEFAULT_LOCALE`**, or `I18n.set_default_locale(...)`, defaulting to
   `en`.

The locale is restored when the request ends, so it never crosses from one
visitor to the next on the same worker. It used to: a controller that never
called `set_locale` rendered in whatever language the previous visitor had
asked for. Realtime frames — Live View and EUI — resolve it from the socket's
session the same way.

`I18n.set_locale` still overrides it for the rest of the request. **It is no
longer something you have to call** to avoid inheriting someone else's language.

```soli
I18n.locale()            # the locale resolved for this request
I18n.set_locale("fr")    # override it, for this request only
```

## Translating

`I18n.translate(key, locale?, translations?)` looks the key up, and falls back
to the key itself when there is no translation — so a missing string shows as
`nav.home` rather than as blank.

```soli
translations = {
  "en.greeting" => "Hello",
  "fr.greeting" => "Bonjour",
  "de.greeting" => "Hallo",
  "en.welcome"  => "Welcome to our app!",
  "fr.welcome"  => "Bienvenue dans notre application!"
}

I18n.set_locale("fr")
I18n.translate("greeting", null, translations)      # "Bonjour"
I18n.translate("greeting", "de", translations)      # "Hallo"
I18n.translate("unknown_key", null, translations)   # "unknown_key"
```

## Plurals follow CLDR

Which suffix a count selects depends on the **language**, not only on the
number. Soli uses the CLDR categories — `_zero`, `_one`, `_two`, `_few`,
`_many`, `_other` — and each language uses the ones it has:

- **French has no zero category**: 0 and 1 are both `_one`, so « 0 article » is
  singular.
- **English** has `_one` and `_other`; 0 takes `_other` — "0 items".
- **Russian and Polish** use `_few` and `_many`; **Arabic** uses all six;
  **Japanese and Chinese** use only `_other`.

Two conveniences on top. A `_zero` key is honoured for a count of 0 in *any*
language when you write one, because "No items" is often worth saying
differently. And a category your file does not declare falls back to `_other`
**in the same locale**, before any other language is consulted.

Before this, every language got English's zero/one/other: a French page with a
correct `fr.yml` asked for `items_zero`, did not find it, and rendered the
English string in its place.

```soli
translations = {
  "en.item_zero"  => "No items",
  "en.item_one"   => "1 item",
  "en.item_other" => "{count} items",
  "fr.item_one"   => "{count} article",
  "fr.item_other" => "{count} articles"
}

I18n.set_locale("en")
I18n.plural("item", 0, null, translations)   # "No items"
I18n.plural("item", 1, null, translations)   # "1 item"
I18n.plural("item", 5, null, translations)   # "{count} items"
I18n.plural("item", 3, "fr", translations)   # "{count} articles"
```

## Numbers, currency, dates

```soli
I18n.format_number(1234.56, "en")            # "1234.56"
I18n.format_number(1234.56, "fr")            # "1234,56"

I18n.format_currency(1999.99, "USD", "en")   # "$1,999.99"
I18n.format_currency(1999.99, "EUR", "fr")   # "€1.999,99"
I18n.format_currency(2500, "JPY", "en")      # "¥2,500"

timestamp = 1768521600                       # 15 January 2026
I18n.format_date(timestamp, "en")            # "01/15/2026"
I18n.format_date(timestamp, "fr")            # "15/01/2026"
I18n.format_date(timestamp, "de")            # "15.01.2026"
I18n.format_date(timestamp, "ja")            # "2026-01-15"  (ISO default)
```

`DateTime.format` takes an optional locale too, when you want the pattern under
your own control and only the month and day names translated:

```soli
dt = DateTime.parse("2024-03-06T14:30:00Z")
dt.format("%A %d %B %Y")         # "Wednesday 06 March 2024"
dt.format("%A %d %B %Y", "fr")   # "mercredi 06 mars 2024"
dt.format("%A %d %B %Y", "es")   # "miércoles 06 marzo 2024"
```

Names are translated for `en`, `fr`, `es`, `de`, `it` and `pt`. Numeric
specifiers (`%Y`, `%m`, `%d`, `%H`, `%M`, `%S`) are unaffected by locale.

## Built-in formatting locales

| Code | Language | Number | Date |
|---|---|---|---|
| `en` | English | `1,234.56` | `MM/DD/YYYY` |
| `fr` | French | `1.234,56` | `DD/MM/YYYY` |
| `de` | German | `1.234,56` | `DD.MM.YYYY` |
| `es` | Spanish | `1.234,56` | `YYYY-MM-DD` |
| `it` | Italian | `1.234,56` | `YYYY-MM-DD` |

## Translation files

```json
{
  "en.app_name": "My Application",
  "en.nav.home": "Home",
  "en.messages.success": "Operation completed successfully!",
  "en.user.greeting": "Hello, {name}!",
  "en.items_one": "You have 1 item",
  "en.items_other": "You have {count} items"
}
```

```soli
en_translations  = json_decode(file_read("config/locales/en.json"))
fr_translations  = json_decode(file_read("config/locales/fr.json"))
all_translations = en_translations.merge(fr_translations)

I18n.translate("nav.home", "en", all_translations)   # "Home"
```

## Method reference

| Call | Answers |
|---|---|
| `I18n.locale()` | the locale resolved for this request |
| `I18n.set_locale(code)` | overrides it for the rest of the request |
| `I18n.set_default_locale(code)` | the fallback when nothing else resolves |
| `I18n.translate(key, locale?, translations?)` | the translation, or the key itself |
| `I18n.plural(key, n, locale?, translations?)` | the CLDR form for `n` in that language |
| `I18n.format_number(n, locale?)` | locale decimal and group separators |
| `I18n.format_currency(amount, currency, locale?)` | `USD`, `EUR`, `GBP`, `JPY` |
| `I18n.format_date(timestamp, locale?)` | a locale date string |
